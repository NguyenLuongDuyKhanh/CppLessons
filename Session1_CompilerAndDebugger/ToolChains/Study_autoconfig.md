That’s a great question — the `"checking for ..."` lines you see during a `make` or `./configure` run are actually part of **Autoconf’s** output, not `make` itself. Let’s break it down clearly:

---

### 🧩 1. Where the “checking for …” comes from

When you build a project that uses the **GNU Autotools** (Autoconf + Automake + Libtool), the build process usually looks like this:

```bash
./configure
make
make install
```

The `"checking for ..."` messages appear during the **`./configure`** step, not during `make`.

They come from macros in the `configure` script that test your system for certain features, headers, functions, or programs.

---

### 🧠 2. What those checks actually do

Each `checking for ...` line means the script is testing something, for example:

```
checking for gcc... gcc
checking whether the C compiler works... yes
checking for C compiler default output file name... a.out
checking for library containing dlopen... -ldl
checking for sys/types.h... yes
checking for inttypes.h... yes
checking for stdint.h... yes
```

Each of these corresponds to a **test** generated by a macro in the `configure.ac` file (for example `AC_CHECK_PROG`, `AC_CHECK_HEADER`, `AC_CHECK_LIB`, etc.).

Autoconf expands these into shell commands that:

* try to **compile small test programs**,
* **run** them if possible,
* and record the result.

---

### ⚙️ 3. What happens under the hood

For example, this line in `configure.ac`:

```m4
AC_CHECK_HEADER([stdio.h])
```

will make `configure` output:

```
checking for stdio.h... yes
```

Behind the scenes, Autoconf actually tries to compile a short C file that includes `<stdio.h>`.
If it compiles successfully, it records the result as `yes`; otherwise, `no`.

It then defines a macro in `config.h` (if that’s part of the setup):

```c
#define HAVE_STDIO_H 1
```

---

### 🧰 4. Why it matters

These checks ensure that:

* your system has the right **compiler, libraries, and headers**,
* optional features can be **enabled or disabled** depending on availability,
* the code can be **portable** across many UNIX-like systems.

---

### 🪵 5. Why you might see it during `make`

Occasionally, `make` re-runs `configure` automatically (if something like `Makefile` or `config.status` is missing or outdated).
That’s why you might see `"checking for..."` lines appear again even when you only typed `make`.

---

### 🧾 Summary

| Command       | What it does                                  | Why you see “checking for…”             |
| ------------- | --------------------------------------------- | --------------------------------------- |
| `./configure` | Tests system features and creates `Makefile`  | Because Autoconf prints test logs       |
| `make`        | Builds the program using generated `Makefile` | Only shows checks if `configure` reruns |
